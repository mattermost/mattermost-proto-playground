Attachment Cards represent a file shared in a channel, message, or task.
Each card shows the file's identity at a glance — type, name, size — and
hosts the actions a viewer can take on it.

Reach for an Attachment Card any time a file is referenced inline. The same
card carries through upload, browsing, and download contexts so users
recognise it across surfaces.

<Divider />

## Anatomy

- <Num>1</Num> **Container** — Elevation 1; rounded corners; clickable surface
  that opens the file or its preview.
- <Num>2</Num> **Filetype icon** — colored glyph that maps to the file type
  (PDF, Word, image, etc.).
- <Num>3</Num> **Filename** — the file's name, truncated with an ellipsis if
  it overflows.
- <Num>4</Num> **Metadata** — file type and size, optionally followed by a
  channel tag and timestamp.
- <Num>5</Num> **Actions** — More options and Download appear on hover in the
  default state; a Cancel/Remove button appears during upload and on
  uploaded-but-not-yet-sent cards.
- <Num>6</Num> **Progress bar** — shown only during upload; spans the bottom
  edge of the card.

## File types

The leading icon is colored to match the family of the file. Code, patch,
text, generic, and zip files use a neutral icon; everything else maps to a
brand color reserved for that family.

## States

The card has three states tied to the lifecycle of the file.

| State     | Use when                                                                           |
| --------- | ---------------------------------------------------------------------------------- |
| Default   | The file lives in the conversation; viewers can download or open it.               |
| Uploading | The author is staging the upload. Shows progress; cancel button replaces actions.  |
| Uploaded  | The file is queued in a draft (e.g. composer). Shows a remove button.              |

## Image thumbnails

When the attachment is an image, swap the file icon for a thumbnail crop.
The rest of the card layout stays the same so cards align in mixed lists.
