A User Avatar Group displays multiple participants as a stack of overlapping
avatars. It's a compact way to show "who's involved" — thread participants,
channel members, call attendees — without a list.

- <Num>1</Num> **Avatars** — overlapping User Avatars; the right-most avatar
  sits on top.
- <Num>2</Num> **Borders** — each avatar wears a small surface-coloured
  border that creates the stacked silhouette.
- <Num>3</Num> **Overflow count** — `+N` chip that appears when more
  participants exist than fit the configured maximum.

## Sizes

The group inherits its sizes from User Avatar but is capped at 72px — beyond
that, a stack stops reading as a group and individual avatars belong on
their own.

| Size  | Use when                                                                          |
| ----- | --------------------------------------------------------------------------------- |
| 20px  | Inline group hints in thread footers, list rows, and message metadata.            |
| 24–32px | Cards, channel info, playbook run participants.                                 |
| 40–72px | Headline group references in profile-style surfaces.                             |

## Number of avatars

Show between **3 and 6** avatars before falling back to an overflow chip.
The default is **3** — err on the side of fewer to reduce noise. The right-most
avatar always sits on top so the stack reads as recently-added-on-the-right.

## Behavior

- Hovering an individual avatar shows a tooltip with that user's name —
  follows the standard tooltip delay.
- Hovering the overflow chip shows the remaining users as a comma-separated
  tooltip ("Dana Lee, Ravi Patel, Wren Cho").
- The overflow chip is auto-managed; it appears only when the number of
  participants exceeds the configured maximum.
