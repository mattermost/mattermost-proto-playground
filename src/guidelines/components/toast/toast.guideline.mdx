Toasts notify the user that an action has completed or surface a brief
message about a system process. They sit on top of the workflow without
interrupting it, don't require user input to disappear, and auto-dismiss
after a short duration.

- <Num>3</Num> **Message** — the line of text. One sentence; complete and
  self-contained.
- <Num>4</Num> **Action button** — optional; for "Retry", "Undo", "View",
  and similar single-step recovery moves.
- <Num>5</Num> **Dismiss button** — optional close affordance for users who
  want to clear the toast immediately.

## Types

Pick the type that matches the message's meaning, not the colour you want.

| Type     | Use when                                                                          |
| -------- | --------------------------------------------------------------------------------- |
| General  | Neutral confirmation with no semantic state (e.g. "Link copied to clipboard").    |
| Info     | Informational follow-up; usually paired with an action ("Refresh", "View").       |
| Success  | A user-initiated action completed successfully.                                   |
| Warning  | Something the user should notice but isn't blocking ("Session expires soon").     |
| Danger   | An error or failure. Always pair with a recovery action when one exists.          |

## Behavior

- **Auto-dismiss** after **3–5 seconds**. Longer messages or messages with an
  action can extend toward the upper end of that range.
- **Stacking** — when multiple toasts queue up, stack them vertically with
  the newest on top. Don't show more than three at once; collapse older ones.
- **Hover** to pause the auto-dismiss timer; resume on mouse-out so users
  reading a toast aren't punished for taking their time.
- **Don't** use a toast for critical information that the user must see —
  reach for a Section Notice, modal, or Global Banner instead.

## Width

| Width      | Use when                                                                          |
| ---------- | --------------------------------------------------------------------------------- |
| Auto-width | The default. Width follows the message and any action.                            |
| Fixed      | The toast lives inside a layout column where alignment with siblings matters.     |

<Divider />

## Content

- One sentence. Past tense for completion ("Saved", "Sent"), present tense
  for state ("Connection lost"), future tense for what's about to happen.
- Don't blame the user. "Couldn't send message" beats "You sent an invalid
  message".
- Pair Danger toasts with an action whenever recovery is possible — Retry,
  Undo, Reconnect.
