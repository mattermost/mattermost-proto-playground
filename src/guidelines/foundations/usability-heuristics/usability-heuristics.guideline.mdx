These heuristics, largely established by NN/g, provide a clear set of
criteria for crafting great user experiences. The following heuristics work in concert with our design principles.

## Visibility of System Status

Mattermost should clearly communicate what the system is doing. Users must
see immediate acknowledgement of their actions, progress indicators for
ongoing tasks, and clear signals when operations succeed, fail, or remain in
progress.

See [System Feedback Guidelines](/foundations/system-feedback).

<Divider />

## Match Between System and Real-World Context

The platform should use concepts and workflows that align with how teams
operate in real life. Use concepts, workflows, and structures familiar to
users (channels, teams, threads). Don't re-invent the wheel. Terminology,
structures (teams, channels, threads), and permissions must reflect the
mental models of enterprise collaboration.

<Divider />

## User Control and Freedom

Users need safe ways to back out of mistakes. Mattermost should be forgiving
and support undo, redo, cancel, and rollback whenever possible, particularly
for destructive actions like deleting, archiving, or leaving channels.

<Divider />

## Consistency and Standards

Consistent patterns reduce confusion. User Interfaces should leverage
standardized components to ensure the experience is designed with
consistency and uniformity. Similar actions should trigger the same types of
feedback, layouts should follow predictable rules, and interactions should
align with conventions users expect from collaboration tools.

<Divider />

## Error Prevention

The best errors are those that never happen. Mattermost should prevent
mistakes through input validation, confirmation for high-impact actions, and
guardrails against misconfiguration or accidental changes.

<Divider />

## Recognition Rather than Recall

Users shouldn't need to memorize commands or workflows. Key actions,
history, and context should remain visible, with menus, shortcuts, and
suggestions supporting efficient recall. Use images or icons to more quickly
recognize interface elements.

<Divider />

## Flexibility and Efficiency of Use

Mattermost should work for both new and expert users. Provide shortcuts,
bulk actions, and keyboard commands for power users, while keeping the
default workflows simple and discoverable.

<Divider />

## Aesthetic and Minimalist Design

Interfaces should focus on essential content and controls. Every element
must serve a purpose, with clutter avoided so users can focus on
communication and collaboration. Consider 'just-in-time' interface elements
to only show extra elements when needed.

<Divider />

## Help Users Recover from Errors

When something goes wrong, users should be able to recover quickly. Feedback
must state what happened, why it matters, and what options are available to
resolve it — including retry or undo when possible.

<Divider />

## Help and Documentation

While the interface should be intuitive, users must have access to clear
help when needed. Role-appropriate documentation, inline tips, and
troubleshooting resources should be readily available without disrupting
workflow.

<Divider />
