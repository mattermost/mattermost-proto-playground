A Popover Menu is a way of displaying multiple choices overlayed on top of the
current context. It displays when interacting with a trigger (such as an icon or
button).

<Divider />

## Anatomy

A Popover Menu is essentially a container that holds the Menu Title, Menu Item,
Menu Group Title, or Menu Divider components.

## Parent and child menus

Submenus allow groups of items to be collapsed under one parent menu item. Menu
Items that trigger submenus are indicated by the chevron icon pointing to the
right.

Submenus should not trigger other submenus to prevent too many layers of
traversal. Consider another navigation pattern if this is required.

### Child menu behavior

Traversing submenus can be difficult for users, so we need to make the
interaction as forgiving as possible. In order to do this, an invisible triangle
is drawn from the center of the Parent Menu Item to the edges of the Child Menu.
It is used to prevent the submenu from closing on angular mouse movement. See
this post for implementation ideas.

### Elevations

Parent Menus use Elevation 4 and Child Menus use Elevation 5.

## Positioning

### Vertical positioning

If the trigger for the popover is at the top of the screen, and there is
vertical room for the popover to fit, the popover should appear 4px below the
trigger button. Otherwise, the popover will need to show 4px above the trigger.

### Child menu vertical positioning

The first menu item in the Child Menu aligns with the selected Parent Menu item.

### Horizontal positioning

If the trigger for the popover is on left half of the screen, the popover should
be left-aligned with the trigger button.

### Child menu horizontal positioning

Child Menus overlap the parent menu horizontally by 8px. If there is room, they
should always open up to the right of the parent menu. In cases where the child
menu needs to open to the left, the chevron icon remains the same — it's more of
an indicator of a submenu rather than a pointer in the direction the menu will
open.

## Menu max-heights

Depending on the location of the menu and its trigger, a menu's max height may be
calculated differently:

- If menu opens above trigger, the max-height is trigger y position − 48px.
- If menu opens below trigger, the max-height is viewport height − trigger y
  position − trigger height − 48px.
- Bottom sheets have max-height = viewport height − 80px.

<Divider />

## Menu widths

The menu width should be sized automatically based on the longest item in the
menu.

### Minimum and maximum widths

Popover Menus should not be less than 144px in width and no wider than 496px.

<Divider />

## Scrolling

For cases where a Popover Menu has more items beyond the menu container's
height, the menu can scroll. If the menu has a Menu Title, the Menu Title
remains fixed to the top as the menu scrolls.

<Divider />

## Accessibility and keyboard behavior

When a menu opens, the keyboard focus is placed on the first item.

- **DOWN** should move the focus to the next menu item, wrapping to the first
  item when it reaches the end.
- **UP** should move the focus to the previous menu item, wrapping from the
  first item to the last.
- **TAB** and **SHIFT+TAB** do not move focus among items within the menu, but
  should move to the next/previous tabbable element outside the menu.
- When a menu item is focused, **ENTER** executes the menu item and closes the
  menu.
- **RIGHT** key: When focus is on a menu item that has a submenu, RIGHT opens
  the submenu and places focus on its first item.
- **LEFT** key: When focused within a submenu, LEFT closes the submenu and
  places focus on the parent menu item that the submenu originated from.
- **ESC** closes the menu and returns focus to the original trigger that opened
  the menu.
